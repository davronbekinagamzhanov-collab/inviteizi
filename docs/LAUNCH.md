# Запуск рекламы: флаги по порядку

Флаги меняются только в Vercel → Settings → Environment Variables (Production), затем **Redeploy**. Значение `true` включает, удаление переменной или любое другое значение — выключает. Перед каждым шагом убедитесь, что миграция `20261115130000_marketing_automation.sql` применена (иначе экран «Промокоды» в админке пишет «ещё не подключены к базе»).

Одна проверка на каждом шаге: свой тестовый заказ с другого Telegram-аккаунта (не админа) → чек → ✅ в админке → ссылка пришла.

## Акции и оптовики (без флага)

Перед первой акцией примените миграцию `20261117120000_promotions_wholesale.sql` (Supabase → SQL editor). Без неё «Новая акция» отвечает «ещё не подключены к базе», цены не меняются.

1. Админка → «🎉 Акции» → «Новая акция»: название, скидка (100 % = бесплатно), начало и конец, тадбиры и форматы. Одна акция одновременно.
2. Проверить: с аккаунта обычного клиента в каталоге — баннер с таймером и зачёркнутые цены; с аккаунта партнёра — без бейджей; тестовый заказ → на проверке старая цена зачёркнута и «Тежайсиз …»; при 100 % — без чека, ссылка сразу.
3. Выключить: «Остановить» — бейджи исчезают сами, неоплаченные заказы при следующем шаге оплаты получают обычную цену.

Оптовик: админка → вкладка «Оптовики» (по № заказа) или карточка партнёра → «Назначить оптовиком». Снять — там же.

Партнёрские ссылки (`join_` из админки → «Партнёры» → «Новый партнёр») работают без флагов: начисление партнёру идёт после ✅, один раз на заказ (проверено тестом).

## Если что-то пошло не так

1. Выключить последний включённый флаг и сделать Redeploy — прежнее поведение возвращается, заказы и начисления не теряются.
2. `/delivery` — какие сообщения не дошли; `/delivery_retry <ключ>` — повторить.
3. Ошибочная оплата — `/refund <номер> <причина>` (начисление партнёру обнуляется, деньги переводите сами).
