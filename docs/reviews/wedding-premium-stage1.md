## Материалы и референсы

Оба внешних сайта (`priglasi.pro`, `nozima-davlatbek-weddingday.lovable.app`) вернули HTTP 403 CONNECT от штатного прокси. Содержимое не было просмотрено; увиденные детали им не приписываются. Использованы реальные локальные рендеры и существующие аудиты `docs/reviews/`.

Повторно использованы существующие WebP с документированной лицензией CC0 1.0 из `public/art/CREDITS.md`:

- `atirgul.webp`: Alex Blăjan, Rose Bouquet (Unsplash), Wikimedia Commons — розы в №96.
- `bodom-guli.webp`: Dulcineia Dias, Almond Blossom (Unsplash), Wikimedia Commons — цветочная полоса №105.
- `samarqand-kitob.webp`: Bernard Gagnon, Registan 01, Wikimedia Commons — архитектура №66.

Новых заимствованных или сгенерированных фотографий нет. Кольца, конверт, складки и портал — самостоятельная CSS-графика; кольца не выдаются за фотографию. Локальные Lora Regular/Italic — имеющиеся файлы с SIL OFL (`assets/fonts/Lora-OFL.txt`). Фото весят примерно 60/36/40 KiB; дополнительных тяжёлых медиа нет. Нижняя фотография №96 загружается лениво. Нет procedural noise, постоянных декоративных циклов или scroll-обработчиков. Основные переходы transform/opacity; статические маски/градиенты не анимируются. Основное содержимое мемоизировано и не перерисовывается при запуске/завершении открытия.

## Совместимость заказов и безопасный выпуск

`templates/order-design.ts` сохраняет старые загрузчики для всех пяти ID. `app/[slug]/page.tsx` использует их для любого заказа без явного `data.designVersion: "premium-v1"`. Исходные компоненты перенесены в `Legacy.tsx` без изменения единого байта (проверено сравнением с origin/main). Это защищает оплаченные и неоплаченные существующие заказы независимо от даты, статуса и количества.

Реальные заказы и Production Supabase не читались и не менялись. Переменные DATABASE_URL и Supabase credentials в этой среде отсутствуют; определить реально используемые ID без доступа к данным нельзя. Защита применяется ко всем пяти, не требует списка заказов, миграции или чтения клиентских данных.

Каталог/демо показывают новые дизайны. Бот не записывает новую версию автоматически: новые и старые заказы без метки пока сохраняют прежнее оформление. **Перед выпуском потребуется отдельное согласованное включение версии для новых заказов**, иначе выбор по новой обложке приведёт к старому рендеру заказа. Это намеренный review-gate, не готовое к публикации изменение каталога. Существующие заказы нельзя массово переключать. Оригинальные OG-обложки оставлены для неизменённых заказов; обновлены пять каталоговых пар WebP/JPEG (WebP для сайта, JPEG для Telegram-бота).

## Проверки

- `npm ci`: успешно; Node 24.19.0, npm 11.9.0.
- `npm test`: **703 passed, 70 skipped**, 47 файлов прошли, 3 PostgreSQL-набора пропущены. Первый запуск внутри sandbox дал два сбоя дочернего Node в release-env; повтор вне ограничений успешно прошёл, код тестов не менялся.
- `npx tsc --noEmit`: успешно.
- `npm run lint`: 0 ошибок, одно существовавшее предупреждение в `app/[slug]/opengraph-image.tsx`.
- `npm run build`: **не прошёл**, внешние Google Fonts остальных шаблонов недоступны через прокси (HTTP 403 подтверждён отдельно). Новые дизайны используют локальные шрифты. Ограничение не скрыто подменой шрифтов или ослаблением TLS.
- Браузерная матрица: [browser-final.json](wedding-premium/browser-final.json), интервалы анимации: [motion.json](wedding-premium/motion.json). Запуск `node scripts/check-wedding-premium.mjs` при работающем dev-сервере. 40 обычных/reduced-motion сценариев плюс 20 сценариев длинных данных на 320/360/375/430 px. Финальные 60/60 сценариев прошли: открытие, загруженные обязательные изображения, отсутствие горизонтальной прокрутки и разорванных слов, наличие событий и карт, аудиовоспроизведение и ошибки консоли. После оптимизации отдельно повторены 145 тестов компонентов и 5 тестов реестра. Музыка из Storage перехватывается локальным WAV; реальные внешние музыкальные файлы не проверены и не изменены.
- Интервалы requestAnimationFrame — только наблюдения Chromium на этой машине с 4× CPU throttling, не доказательство стабильных 60 FPS и не замена проверке физических iPhone/Android. Финальный max интервала: №96 — 100.0 мс, №105 — 83.3 мс, №66 — 66.6 мс, №104 — 66.7 мс, №106 — 83.4 мс; в каждом прогоне 1–2 интервала >50 мс. Задержки остаются риском на слабых устройствах.
