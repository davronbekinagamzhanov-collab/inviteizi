## Текущее поведение

Открытие `split-v3`: короткое движение сургуча, верх конверта уходит вверх, низ — вниз. Сразу появляется само приглашение; лист не выдвигается. Обложка → приглашение → календарь → программа → адреса → финал. У трёх тем единый порядок и своя стилистика.

Используются существующие `InvitationData.photos` и `clientPhotos`. Место 1 — обложка, 2 — приглашение, 3 — финал. Фотография клиента имеет приоритет над локальным образцом; четвёртая не используется. Без своих фотографий показаны два спокойных кадра, а не лента из мелких деталей. Фотографии залов и фото в пунктах программы убраны. Название, адрес и кнопка карты берутся из существующих событий и mapLink; координаты открываются штатным HTTPS-адресом 2ГИС. Нет дресс-кода и новых полей заказа.

## Почему Git Preview блокировался

Vercel Hobby для приватного Git-репозитория проверяет связь автора коммита с владельцем Hobby-проекта. В истории этого проекта Git-коммиты cc9647a и a251c03 получили BLOCKED, а авторизованные владельцем коммиты 9713423 и 658b18f получили READY. Git-интеграция подключена и работает; проблема не в README и не в коде сайта.

Официальная документация: https://vercel.com/docs/deployments/troubleshoot-project-collaboration

Нельзя исправлять это подстановкой имени/email владельца в Git, изменением автора старых коммитов или использованием чужого токена.

## Порядок работы без ручных README-коммитов

1. Проверить TypeScript, ESLint, тесты и сборку в рабочей ветке.
2. Сохранить проверенное дерево через подключённый GitHub API, аутентифицированный самим владельцем. Не передавать `author`/`committer`: GitHub сам определяет их по действительной авторизации. Участие AI явно отметить в сообщении (`Co-authored-by: Codex`). Это авторизованное действие подключённого аккаунта, а не изменение локального Git email.
3. Проверить серверный SHA и соответствие дерева локальным проверенным файлам; обновлять только ref `feature/vip-invitations` с проверкой ожидаемого родителя.
4. Найти Deployment именно для этого SHA и этой ветки. Дождаться `READY`. Старый READY другого SHA не является публикацией новых изменений.
5. Если Git-триггер не сработал, допустим официальный Preview API от аутентифицированного владельца с точным SHA. Не менять production, тариф, Git-авторство или глобальную защиту проекта ради обхода отказа.
6. На защищённом Preview использовать существующую Vercel-авторизацию или официальный временный Share URL для конкретного deployment. Защиту production не отключать. Share URL доступен получившему ссылку до истечения срока; не сохранять его в репозитории.
7. Открыть настоящий HTTPS Preview через Playwright и проверить все три `/demo/<id>`. Вернуть новые ссылки, SHA, READY и фактические результаты. При отказе сервиса — `BLOCKED`, без подмены старым URL.

Этот порядок не требует Vercel CLI-токена в репозитории, смены тарифа или дополнительного коммита README. Подключение GitHub должно принадлежать владельцу, который действительно разрешил его использовать. При отсутствии подходящего подключения не маскировать отказ: потребуется однократно подключить собственный GitHub/Vercel аккаунт владельца.

## Проверка настоящих страниц

`VIP_ORIGIN=https://<exact-ready-deployment>.vercel.app VIP_COMMIT_SHA=<full-sha> VIP_DEPLOYMENT_ID=<id> node scripts/vip-shots.mjs`

Для защищённого Preview `VIP_ACCESS_FILE` может указывать на локальный приватный JSON с официальным временным Share URL (`{"url":"..."}`). Он не коммитится и не печатается в отчётах. `VIP_REPORT_DIR` задаёт каталог локальных QA-артефактов. Локальная отладка отдельно разрешается `VIP_ALLOW_LOCAL=1` и не считается проверкой опубликованного сайта.

Проверки: 320/360/390/430 px, версия `split-v3`, короткое открытие и отсутствие листа, календарь, прокрутка, пауза/воспроизведение музыки, карты с реальным нажатием, один переключатель языка, отсутствие фото залов и горизонтальной прокрутки, консоль и загрузка фото.

Ограничения: Chromium с мобильным viewport не заменяет физический iPhone/Safari; переход в нативное приложение 2ГИС проверяется на телефоне. Продажу, реальную загрузку фото через Telegram и отправку RSVP в рабочую БД в таком тесте не выполняем. Три клиентских слота проверяются отдельными тестами без создания заказов.
