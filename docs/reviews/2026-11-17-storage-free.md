Прод-база, бот, переменные Vercel не трогались. SQL — только файлом.

## Что сделать владельцу (по порядку)

1. **Vercel → проект inviteizi → Storage → Create Database → Blob** → имя `inviteizi-files`, доступ **Public** → **Create** → **Connect to Project** (Production и Preview, префикс пустой) → **Redeploy**. Переменная `BLOB_READ_WRITE_TOKEN` появится сама. Подробно — `docs/LAUNCH.md`.
2. Положить песни библиотеки в `public/audio/lib/<тадбир>/<имя>.mp3` (список ниже), задеплоить.
3. Supabase → SQL editor: `supabase/release/music-local-urls.sql` — сначала шаг 1 (только чтение, покажет точный список файлов), открыть 2–3 новых адреса в браузере, потом шаг 2.
4. Проверить на телефоне: фото в анкету (бот и Mini App), своя песня mp3 → «Тайёр», приглашение с этой песней играет.

**Лимиты Vercel Blob на Hobby.** Страницы vercel.com из этой среды не открываются (сеть закрыта), поиск по документации Vercel таблицу цен не вернул — проверить цифры не удалось. По моим данным (сверить в Vercel → Usage → Blob): Blob доступен на бесплатном Hobby; в месяц входит около 1 ГБ хранения, 10 000 простых операций (чтения без кэша), 2 000 сложных (загрузка, удаление, список), 10 ГБ трафика; при превышении на Hobby хранилище останавливается до следующего месяца (без списания денег). Наша нагрузка: фото ≤ 600 КБ, песни ≤ 12 МБ, кэш на год. Самое тяжёлое — свои песни: 10 ГБ ≈ 800 полных прослушиваний песни 12 МБ в месяц; музыка библиотеки идёт с сайта и в лимит Blob не входит.

## Пункт 3. Проверка здоровья

| Что | Как работает | Проверено |
|---|---|---|
| Файлы | cron каждые 10 мин: песня с сайта (`/audio/originals/…`, Range 0-1) и `health/ping.txt` в Blob (если его нет — кладётся сам). Два сбоя подряд → «⚠️ Файлы не открываются (код N): музыка/фото у клиентов не работают», не чаще раза в час; восстановились → «✅ Файлы снова работают». Мимо кэша — раз в час, чтобы не тратить операции Blob | `bot/health.test.ts` (5 сценариев) |
| База | перед заданиями cron — `select 1`. Не отвечает → «⚠️ База данных не отвечает…» раз в час (время помнится в Blob, без Blob — в памяти), остальные задания не запускаются (503); ожила → «✅» | `bot/health.test.ts`, `bot/marketing-pg.test.ts` (Postgres) |
| Кому | `OWNER_TELEGRAM_ID`, если нет — `ADMIN_IDS` | тест |

Ограничение: cron запускает сама база (pg_cron). Если база лежит полностью, cron не придёт и сообщения не будет — проверка ловит «база жива, но сайт до неё не достаёт».
