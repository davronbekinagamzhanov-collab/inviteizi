# Задача №2 — Муҳр / Ипак / Муҳрли мактуб

База main `bb599e9afa8aa7faacb3810559528ca52d652b6d`, отдельная feature/nikoh-envelope-polish. PR #13 (3c36f6c) и #14 (5cfe683) изучены, их код не переносился и ветки не менялись. Нет merge, production, API/бот/DB операций или изменения цен/registry/capabilities.

## Художественные решения

- **Муҳр**: сохранён прохладный голубой характер; вместо плоских градиентных треугольников — фотографические слои хлопковой бумаги с тенями сгибов. Самостоятельный прозрачный сургуч с двумя соединёнными оливковыми ветвями означает союз, вместо AM. Печать разделяется, верхняя бумажная часть откидывается, карман опускается; текст скрывается до поворота, поэтому перевёрнутых имён нет. За обложкой — пара со спины у цветущего свадебного входа, деталь букета и церемониальный двор в одной голубовато-молочной/шалфейной палитре. Крупнее главный кадр, спокойнее регистр и ритм имён.
- **Ипак**: убраны autoplay silk video и его размытый poster, x-earrings, ipak-bouquet, ipak-hands, дополнительный случайный ipak-silk. Вместо них — три кадра одной тёплой свадебной истории: пара в узбекском дворе, свет сквозь фату у свадебного входа, вечерний свет на цветущей веранде. Обложка чёткая, мягко поднимается; сохранён журнальный разворот. Третий фото-слот виден в основной странице, не повторяется в подписи. Если клиент дал своё первое фото, оно используется также на обложке с contain без размытия.
- **Муҳрли мактуб**: двустворчатое пудровое письмо с тиснением миндального цветка и живыми ветвями вместо ещё одного треугольного конверта. Створки расходятся в стороны; их физическая фотографическая фактура, рельеф и тени сохранены. После открытия — цветущий свадебный сад и читаемые имена на светлом поле, без монограммы и двойной арочной SVG-рамки. Цветение продолжается в финале.

Это свадебные сцены, а не три натюрморта с аксессуарами. Лица не показываются; нет текста, логотипов или зашитого языка в кадрах. Исходники созданы image_gen по прямому разрешению пользователя (узкое исключение из исторического запрета AGENTS на AI). Это **сгенерированные фотореалистичные изображения**, не документальные снимки. CSS лишь размещает/анимирует фотографические слои, не выдаётся за фотографию.

Оптимизированные WebP, исходные filename/SHA256, размеры и tool: `public/art/nikoh-envelope/provenance.json`. Оригинальные PNG остаются неизменными в workspace/generated_images. Обложки/thumbnail/OG обновлены только для трёх целевых ID. Для обложки Муҳр использован исходный закрытый конверт exec-20be2e4a-1556-44f5-9a0b-f8c940a7dbfb.png; отдельные paper/wax получены редактированием этого изображения через image_gen. Старые общие материалы не удалены: ими могут пользоваться другие шаблоны.

## Механика и совместимость

Новый scoped WeddingOpening импортирован только тремя целевыми дизайнами. useInvitation, InvitationShell, FloralInvitation, data/order loaders, API и registry не изменены. Формат Animated, стоимость, ID/пути и старые оплаченные ссылки сохраняются. Полные поля хозяев/семей, 1–3 события, карта каждого места, календарь, countdown, музыка клиента/резервные мелодии, UZ/RU и RSVP остаются существующими.

Муҳр/Ипак сохраняют три клиентских фото; полная и частичная замены проверяются отдельно, пустые slots берут новые согласованные defaults. У Муҳрли мактуб clientPhotos остаётся false; переданная лишняя фотография не начинает показываться. Гидратация завершает подготовку кнопки, ref блокирует повторный запуск в одном цикле, таймеры очищаются при unmount. Открытие занимает примерно 1.65–1.75 с; reduced motion завершает его без ожидания. Непрозрачная подложка до декодирования фото исключает просвечивание страницы при холодном старте.

## Контроль качества

До/после 390 сохраняются отдельно для каждого дизайна: закрыто, открыто, вся страница; новая механика также проверяется промежуточными browser-кадрами. Снимки кадров фиксируют состояние на машине проверки, не являются измерением FPS или точной временной шкалой телефона. Нельзя сравнивать загруженную новую фотографию с недогруженной старой: baseline main переснят с доверенным CA и ожиданием загрузки.

Профильные tests: настоящие компоненты demo/full × 1–3 события, длинные данные, семейные поля, ссылки карты, клиентские фото/partial defaults/no-photo capability; actual paid-slug route с тремя active/full fixtures без БД. Дополнительно registry, порядок каталога, прежние legacy-компоненты, natural assets и бюджет thumbnail.

Browser QA: три шаблона × 320/360/375/390/430, UZ/RU, открытие/двойное касание, фотографии, прокрутка, календарь/countdown, фактический play/pause audio и переход 2ГИС на 390, pageerror/console error. Reduced motion — клавиатура Enter/Space и повтор после reload. Временный **локальный** fixture route предоставляет настоящие длинные props, три события, три клиентских фото и RSVP demo без POST; он удаляется перед финальной сборкой и не попадает в PR/Preview. Финальные числа проверок, точный commit/deployment и READY фиксируются в Draft PR после HTTPS QA.

Ограничения: не проверены физический iPhone/Safari/Telegram WebView, нативное приложение 2ГИС, настоящий upload через бот/Storage и живые оплаченные заказы/RSVP/платежи. Их не трогаем; данные/оплаченный маршрут проверяются синтетическими fixtures. После Preview остановиться на утверждение владельца.

Локальная приёмка до публикации: 49 tests в 6 файлах PASS (26 целевых render/photo/paid-route + 23 registry/catalog/legacy/natural/budget). 15 default browser cases PASS; отдельно 21 fixture/reduced-motion/demo-RSVP case PASS. Временные app/review-envelope страницы и их сгенерированные dev-типы удалены до release build. ESLint без ошибок/предупреждений. Изолированный webpack baseline main потребовал вручную подключить его же выпущенные CSS chunks темы и natural/floral для корректного сравнения; исходный код main не менялся. Webpack также выдавал эти CSS как script с SyntaxError — это воспроизводится на исходном main, и не исправляется глобальной архитектурной правкой в этой задаче. Для финальной проверки рабочая копия получила обычную независимую копию установленных node_modules вместо внешнего symlink, затем используется штатный Turbopack, как на Vercel. Новые финальные страницы проверяются без вмешательства в CSS.

Финальная штатная сборка Turbopack и standalone TypeScript PASS. Browser на production build без инъекций стилей: **18/18 PASS** (15 mobile default + 3 reduced-motion/reload/keyboard). Проверка включает 375×812, Range-проверку границ текста и отсутствие pageerror/console error. Все три новых закрытых/открытых вида 390 повторно просмотрены и сравнены с исходными. Preview должен использовать именно новый SHA; окончательные HTTPS результаты фиксируются в PR, без дополнительного README-коммита.
