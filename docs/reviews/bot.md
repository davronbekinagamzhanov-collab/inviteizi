Всё проверено тестами: FakeTg вместо Telegram, MemoryRepo вместо базы, часы подменяются. Живой бот не трогал: setWebhook не вызывал, сообщений не слал.

## Схема шагов

```
/start [payload] ─(новый)→ язык [🇺🇿][🇷🇺] → приветствие + меню (reply-клавиатура)
меню: 💌 создать │ 📂 мои │ ❓ помощь │ 🌐 язык     (/my /help /lang /new)

cat ─→ fmt (+ℹ️ alert) ─→ catalog (◀ n/N ▶ · 👁 Намуна url · 🛒)
  никоҳ:   groom → bride → relation[фарзандларимиз/набираларимиз/ўзимизники] → hosts → sideAsk ─(ҳа)→ sideBride
  наҳорги: person → relation[ўғлимиз/қизимиз/набирамиз/укамиз/ўзимизники] → cause[никоҳ/суннат] → hosts
  суннат:  person («А ва Б») → relation[ўғлимиз/набирамиз/укамиз/фарзандимиз] → hosts
  ─→ evDate (календарь) → evTime (кнопки | ✍️ → evTimeCustom ЧЧ:ММ) → evVenue → evAddress → evLoc
  ─→ more [🍚 наҳорги][🌸 келин салом][🎊 тўй базми][✅ тамом]  (до 3; добавленный: evSameDay «худди шу кунми?»)
  ─→ text [1][2][3][✍️ свой → textOwn ≤600] ─→ music [список → musicList ▶/✅][своя → musicOwn ≤20 МБ][без]
  ─→ review (✏️ имена / кем / хозяева / стороны / повод / каждый тадбир → evMenu / текст / музыка / дизайн; ✅)
  ─→ заказ status=preview, slug из имён → ссылка на НАМУНА + [💳 Тўлаш][✏️]
pay:N → awaiting_payment, реквизиты + [📋 копировать номер] + [📎 чек] → receipt (фото/PDF) → receipt_sent
  → админам: чек + карточка + [✅ ok:N][❌ no:N → причины nr:N:money|sum|other]
  ✅ → active, paidAt, expiresAt; клиенту: ссылка, QR (PNG), текст для гостей + [📤 t.me/share]
  ❌ → rejected; клиенту причина + [📎 rcpt:N] → снова receipt_sent → снова админам
мои: edit:N (сводка заказа, slug не меняется) · pay:N · slug:N (новая ссылка) · 📞 t.me/OWNER
cron: чек ждёт > 30 мин → админам 1 раз; preview/awaiting_payment > 3 ч → клиенту 1 раз; expiresAt прошёл → archived
```

Как устроен диалог:
- Шаг и черновик хранятся в `users.step` / `users.state`.
- Кнопка вопроса выглядит как `a:<номер вопроса>:<значение>`. Кнопки старых вопросов не срабатывают: бот показывает всплывашку «кнопка устарела».
- Стек «Назад» (`state.back`) хранит только шаг и номер тадбира, сами данные не откатываются. Брошенный на полпути тадбир убирается.
- На сводке стек «Назад» обрезается, поэтому правки не копят шаги.

## Решения (принял сам)

1. **Обложки каталога** берутся по адресу `${PUBLIC_BASE_URL}/covers/<id>.jpg`, как в спеке. В реестре указан `.webp`, но Telegram по ссылке надёжно принимает только JPG. JPG генерирует `scripts/make-covers.mjs`, папки `public/covers` пока нет.
2. **Первый тадбир — главный** (никоҳ базми / наҳорги / суннат базми), добавленные идут следом в порядке добавления. Сортировки по времени нет: `events[0]` — это таймер.
3. **Добавленный тадбир.**
   - Наҳорги ош и тўй базми: вопрос «Худди шу кунми?».
   - Келин салом: сразу календарь, потому что он обычно на следующий день.
   - Добавленному наҳорги время ставится 06:00 без вопроса (по спеке), его можно поменять в сводке.
   - Время для келин салом: 08:00–11:00.
4. **«Кем приходится» для суннат**: ўғлимиз, набирамиз, укамиз, фарзандимиз. Вариант «ўзимизники» для суннат не имеет смысла.
5. **Текстов показываю максимум 3** (`inviteOptions().slice(0,3)`): у никоҳ их 4, в спеке сказано «3».
6. **Время можно написать** и на шаге с кнопками времени: «18:30» принимается.
7. **Сообщение для гостей всегда на ўзбекском**, даже у русскоязычного клиента: его читают гости. Тексты лежат в `uz.guest`.
8. **Причина отказа** в базе хранится по-узбекски (`rejectReason`), клиенту показывается на его языке.
9. **Правка оплаченного заказа:** дизайн меняется только в том же формате (сразу каталог, цена та же), slug не меняется, `expiresAt` пересчитывается по новым датам. У неоплаченного смена формата меняет цену.
10. **Чек**: фото или документ (PDF/картинка). Реквизиты сразу переводят клиента на шаг «жду чек», кнопку «📎» можно не нажимать.
11. **Напоминания cron**: одна попытка. Если клиент заблокировал бота, отметка всё равно ставится, чтобы не слать каждые 10 минут. Ошибки считаются в поле `errors`.
12. **Webhook отвечает 200 даже при ошибке логики** (ошибка пишется в лог), иначе Telegram повторяет обновление бесконечно. Секрет сравнивается через `timingSafeEqual`.
13. **Решения по чеку (`ok/no/nr`) работают у админа без выбранного языка.** Права проверяются на сервере через `repo.isAdmin` при каждом нажатии.
14. **Новая ссылка** (`slug:N`): латиница, цифры и «-», длина 3–40. Запретные адреса берутся из `lib/slug.ts` (`isReservedSlug`), занятость — из `repo.isSlugTaken`.
15. **Статистика в MemoryRepo:**
    - «сегодня» считается с полуночи UTC+5, «неделя» — 7 суток, «месяц» — 30 суток;
    - выручка — по `paidAt` заказов active/archived;
    - `bySource.paid` — число оплаченных заказов, пользователи без source идут как «—».

    У БЭКЕНДа (repo-pg) стоит сверить эти правила.
16. **slugify**: сначала был временный `bot/slug.ts`. Когда появился `lib/slug.ts` БЭКЕНДа, перешёл на него и удалил временный файл. Мои случаи из `helpers.test.ts` проходят на `lib/slug`.
