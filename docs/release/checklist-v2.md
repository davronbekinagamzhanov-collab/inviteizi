## 3. Merge и выкладка

1. GitHub → PR из `feature/v2` → **Merge**. Vercel выложит сам (3–5 минут), дождаться **Ready**.
2. **Проверка домена** (1 ноября был откат — после отката Vercel перестаёт сам переводить домен на новые выкладки):
   Vercel → проект `inviteizi` → **Deployments**. Если сверху жёлтая плашка «Production domains are not being
   automatically assigned» или у новой выкладки нет метки **Current** — нажмите на новой выкладке **… → Promote**

   страница приложения (не 404).
3. Кнопка меню у всех: в терминале
   `node --env-file=.env.local scripts/telegram-setup.mjs --menu` — у поля ввода появится «✨ Очиш» (открывает приложение).
   При `MINI_APP_ENABLED=false` та же команда вернёт обычное меню команд. Webhook и профиль не меняются.
4. Если включили казахский: `node --env-file=.env.local scripts/telegram-setup.mjs --commands` — команды бота на казахском.

## 6. Бэкап базы — каждый день (GitHub, бесплатно)

Файл `.github/workflows/db-backup.yml` уже в репозитории: каждую ночь в 02:17 (Алматы) снимает копию базы и хранит
её 14 дней во вкладке **Actions** репозитория. Нужно один раз дать ему строку подключения:

1. **Где взять строку.** Supabase → проект → кнопка **Connect** (вверху) → вкладка **Connection string** →
   режим **Session pooler** (порт 5432; не «Transaction»). Скопируйте строку вида
   `postgresql://postgres.hjakyirmyauqhurkqhsn:[YOUR-PASSWORD]@aws-0-….pooler.supabase.com:5432/postgres`
   и вместо `[YOUR-PASSWORD]` вставьте пароль базы (Supabase → Project Settings → Database → Database password;
   если не помните — там же **Reset database password**, но тогда обновите и `DB_SERVER_PASSWORD`/`DATABASE_URL` в Vercel).
2. **Куда вставить.** GitHub → репозиторий `inviteizi` → **Settings** → **Secrets and variables** → **Actions** →
   **New repository secret**. Name: `DB_BACKUP_URL`, Secret: строка из шага 1 → **Add secret**.
3. **Проверить.** GitHub → **Actions** → «db-backup» → **Run workflow**. Через 1–2 минуты — зелёная галочка, внизу
   страницы запуска в **Artifacts** файл `inviteizi-ГГГГ-ММ-ДД.dump` (несколько МБ). Пока секрета нет, запуск зелёный,
   но с предупреждением «бэкап пропущен».

**Как восстановить** (если базу испортили): скачайте нужный `.dump` из Actions → Artifacts, распакуйте zip и на
компьютере с установленным PostgreSQL 17 выполните (строка — та же Session pooler):
`pg_restore --clean --if-exists --no-owner --schema=public -d "СТРОКА" inviteizi-ГГГГ-ММ-ДД.dump`
В дампе есть права (GRANT) и политики RLS — после восстановления бот сразу снова может читать и писать.
Проверка: `select count(*) from public.orders;` и открыть в боте «📊 Статистика».
Восстанавливаете в **новый** проект Supabase (не боевой) — сначала в нём SQL Editor:
`create role inviteizi_server;`, затем та же команда. Файлы (фото, песни) в бэкап не входят: они лежат
в Storage Supabase отдельно. Бэкап по расписанию заработает после Merge в `main` (GitHub запускает расписание только из
основной ветки); до этого — кнопкой «Run workflow», выбрав ветку `feature/v2`.
