# Выпуск ветки feature/natural-pilots (PR #8) — порядок для владельца

Всё ниже — только после вашего «да». Каждый SQL — в Supabase → SQL Editor, целиком, одной вставкой.
Каждый файл можно запускать повторно: второй раз ничего не меняет. Если номер дизайна в базе уже занят чужим — файл
сам откатывается и пишет «conflict», ничего не ломая.

Почему такой порядок: сайт и бот берут список дизайнов из кода, а не из базы. Таблица `templates` нужна только как
справочник для заказов (заказ ссылается на строку дизайна). Поэтому строки новых дизайнов кладём ДО выкладки кода —
старый бот их не видит, а новый сразу может принять заказ.

## 4. Проверка в боте (5 минут)

1. `/start` → «💌 Таклифнома яратиш» → **Никоҳ**: видны 3 формата (Анимацияли 8 000, Варақланадиган 6 000, Оддий 5 000).
2. В каждом формате листаются обложки; у дизайнов с фото — значок фотоаппарата на обложке и строка «📷 …» в подписи.
3. То же для **Наҳорги ош**, **Суннат**, **Юбилей** — ни один формат не пустой.
4. Выбрать «Нур варақ» (с фото) → дойти до вопроса «📷 Таклифномага расмларингизни қўшасизми?» → отправить 1 фото → в превью фото на первом экране.
5. Вернуться и выбрать «Ислими варақ» (без фото) → шага фото нет, превью без фото, цена та же.
6. Платить не нужно: проверка заканчивается на ссылке с «НАМУНА».

## Если что-то пошло не так

- SQL выдал «conflict» — ничего не изменилось. Пришлите текст ошибки разработчику.
- Сайт после Merge с ошибкой — в Vercel → Deployments → предыдущая выкладка → **Promote to Production**. Строки
  из шагов 4–6 мешать не будут: старый код их не видит.
